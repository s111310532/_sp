一、 核心觀念釐清

1. 標準輸入、輸出與錯誤 (stdin, stdout, stderr)

當一個行程被建立時，系統預設會自動為它開啟三個檔案描述符：

0 (stdin / 標準輸入)：預設連結到鍵盤。程式讀取 0 就是在讀取使用者的輸入。

1 (stdout / 標準標準輸出)：預設連結到螢幕。程式對 1 寫入資料，螢幕就會顯示字串。

2 (stderr / 標準錯誤輸出)：預設連結到螢幕。專門用來輸出錯誤訊息，與 1 分開的好處是方便將一般輸出與錯誤訊息分流（例如在終端機使用 2> error.log）。

2. 行程控制：fork() 與 execvp()

這是 Unix 系統建立與執行程式的「兩階段進化論」：

fork()：複製目前行程。它會創造出一個跟原本一模一樣的「子行程」（包含記憶體、變數、打開的檔案描述符通通複製一份）。

在父行程中，fork() 回傳子行程的 PID。

在子行程中，fork() 回傳 0。

execvp()：覆蓋目前行程。它會把一個全新的執行檔（如 ls, grep）載入到目前的行程空間中，徹底取代原本的程式碼，並從新程式的 main 開始執行。注意：execvp 執行成功後就不會返回，而且它會繼承原本行程打開的檔案描述符。

3. 檔案操作：open(), close(), read(), write()

這是最底層的系統呼叫（System Call）：

open()：打開一個檔案，系統會回傳目前最小且未使用的 fd（整數）。

close()：關閉該 fd，釋放該整數與資源。

read(fd, buf, size)：從 fd 讀取 size 個位元組到 buf。

write(fd, buf, size)：把 buf 裡的 size 個位元組寫入 fd。

4. 關鍵魔法：dup2(oldfd, newfd)

dup2 是實現 I/O 重導向（Redirection, 如 shell 中的 > 或 |） 的核心。
它的功能是：「把 newfd 關閉（如果原本有開），然後讓 newfd 複製並指向 oldfd 所指向的檔案。」

例如：dup2(file_fd, 1);
這行程式會讓 1（stdout）不再指向螢幕，而是改為指向 file_fd（某個檔案）。之後程式只要呼叫 printf 或 write(1, ...)，內容就不會印在螢幕上，而是自動寫進檔案裡。

二、 I/O 重導向與 dup2 的運作原理

初始狀態：行程的檔案描述符表格中，0 指向鍵盤，1 與 2 指向螢幕。我們用 open() 打開了 output.txt，系統分派了 3 給它。

執行 dup2(3, 1) 後：原本指向螢幕的 1 被強制改為指向 output.txt。此時 1 和 3 同時指向該檔案。隨後我們用 close(3) 把 3 關掉，只留下 1。這時候，這個行程的所有標準輸出（stdout）就被神不知鬼不覺地導向到檔案裡了。
