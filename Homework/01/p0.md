一、while 設計原理詳解

1.記住起點： 用 cond_pc 存下條件運算開始前的地址（例如 100）。

2.開出空頭支票： 生成 JMP_F, cond, -, ?。這時最後一個參數填 ?，但用 jmp_f_idx 記住這條四元組的編號。

3.編譯迴圈主體： 繼續編譯大括號內的程式碼，這會產生一系列新的中間碼。

4.折返回起點： 主體結束時，產生一條無條件跳轉 JMP, -, -, cond_pc，讓控制流能繞回起點重新檢查 count < 3。

5.兌現支票（回填）： 此時迴圈程式碼全部生成完畢，當前的 quad_count 就是迴圈外的第一條指令。編譯器這時回頭找到 quads[jmp_f_idx]，把原本的 ? 修改成當前的 quad_count。

二、本編譯器的函數呼叫機制如何運作

1. 參數收集與傳遞（呼叫前）
當 Parser 解析到 add(x, y) 時，會觸發 factor() 裡的呼叫邏輯：

  •它會走進一個 while 迴圈，依序解析 x 與 y。

  •每解析完一個參數，就會立刻發射中間碼：PARAM x、PARAM y。

  •VM 執行期行為： VM 遇到 PARAM 指令時，會將 x 和 y 的實際數值（10 和 20）依序推進一個獨立的全域暫存區：param_stack。

2. 環境切換與動態鏈結（執行 CALL）
Parser 計算完參數後，發射中間碼：CALL add 2 t1（呼叫 add，有 2 個參數，結果存入暫存變數 t1）。
當 VM 執行到 CALL 時，會進行以下核心操作：

  •推進 Stack 指標： 執行 sp++。這等同於在記憶體中開闢一塊全新的空間（New Stack Frame）給 add 函數。

  •保存返回資訊（動態鏈結）： * 將當前 pc + 1 存入 stack[sp].ret_pc。這能確保函數執行完後，虛擬機能回到主程式繼續做 * 2。
                        將目標變數 t1 存入 stack[sp].ret_var。這紀錄了等等要把返回值寫回主程式的哪一個格子。
  •搬移參數： 函數利用 p_count（此處為 2）從全域的 param_stack 中取出最後推進去的 2 個值，複製到新 Frame 的 incoming_args 陣列中。

  •跳轉跳躍： 將 pc 設為 add 函數的指令起點。

3. 形參綁定與執行（進入 Callee）
進入函數後，首先會遇到中間碼 FORMAL a 和 FORMAL b（形式參數）。

  •VM 執行期行為： 函數透過內部計數器 stack[sp].formal_idx，將剛剛傳進來的 incoming_args[0]（值為 10）指派給當前作用域的變數 a；incoming_args[1]（值為 20）指派給 b。

  •接下來函數內部執行 sum = a + b 時，get_var 和 set_var 都只會作用在當前 sp 所指向的 Frame，實現了區域變數的隔離。

4. 銷毀與返回值回寫（執行 RET_VAL）
當函數執行到 return sum; 時，會生成中間碼 RET_VAL sum。
VM 執行退棧（Pop Frame）的動作極其優雅：

  •虛擬機先用區域變數把 sum 的值（30）、返回地址（ret_pc）以及要寫回的暫存器名稱（ret_var 也就是 t1）存起來。

  •執行 sp--。這一步瞬間銷毀了 add 函數的作用域，所有 add 內部的 sum、a、b 變數隨之從堆疊中消失。

  •作用域回到主程式（sp 減 1 後的位置）後，執行 set_var(target_var, ret_val)。這時，值 30 被成功寫入了主程式的暫存變數 t1 中。

  •將 pc 指向剛才存下來的返回地址，主程式順利接棒，繼續拿 t1（值 30）去乘以 2。
